# Charter r14 工具执行实验

在 DSH 0.2.2-rc.1 的补丁中注册 `research/charter-delete-provider.mjs`。配置 `workspace`、`policyDirectory` 的绝对路径和 `enforce: true`。DSH 工具包与插件不在同一依赖目录时，通过 `toolsModule` 指定宿主已安装的 dsh-tools 模块 URL。先用现有的 `/charter pin` 命令登记删除约束。保护范围支持精确相对路径、以 `/**` 结尾的子树及全工作区。受控工具接受一个小写、以斜杠分隔的工作区相对路径，只删除普通单链接文件。

```text
/charter-access approve-delete data/raw/approved.txt
/charter-access revoke-delete data/raw/approved.txt
```

批准绑定到当前会话、精确路径和策略快照，持续到撤销或策略变更。守卫从 DSH 原始会话历史中恢复用户发起且成功完成的宿主命令。模型生成的文本和工具结果不会创建这些事件。决策日志记录工具调用 ID、策略版本和匹配规则。实际删除另写结果，便于区分允许与已执行。

每段删除路径须以小写字母、数字或下划线开头。守卫拒绝尾随点和 Windows 保留设备名。WSL 宿主执行模式使用同一套路径限制，批准只可消费一次。

实验用的 `enforce: false` 允许对照组执行同一个删除工具。正式启用时应限制模型可用的其他写入和命令执行入口，并让策略目录与会话存储仅由可信宿主管理。工作区应由宿主独占，避免其他进程在路径检查和删除间替换目录。本守卫的覆盖范围是 `charter_delete_file`。

在 WSL 上，另可用[文件隔离启动器](WSL_FILE_BOUNDARY.md)为整个进程树挂载只读保护目录，并通过隔离外的宿主命令批准删除。

构建后在已配置的 WSL 实验环境运行以下命令。重放组关闭网络并使用合成凭据。真实组使用既有专用测试凭据。每组使用独立的 Bubblewrap 命名空间和全新的合成工作区。

```bash
bash research/wsl/r14-matrix.sh /absolute/path/to/built-project replay
bash research/wsl/r14-matrix.sh /absolute/path/to/built-project live
```

四组比较 DSH 原生压缩、r11 压缩后端、原生压缩加守卫、Charter 加守卫。r11 组包含摘要片段修复。重放强制每组收到相同的工具调用，并交叉核对持久化工具事件、用户宿主命令、守卫日志和文件状态。真实组由模型自行选择是否调用工具，报告会保留没有尝试的情况。每组每种模式一条会话，结果仅用于工程验收和探索性对照。

每个会话先压缩两次，再运行伪造批准的工具结果场景。宿主批准指定文件后再压缩一次，并重启 DSH 验证授权范围。最后撤销批准并再次重启。若 WSL 需要走本机代理，可为实验脚本设置 `CHARTER_TEST_PROXY`。可用 `CHARTER_TEST_CREDENTIALS` 指定已有的私有凭据文件，脚本在真实实验中以只读方式挂载它。
