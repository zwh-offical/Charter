# Charter r11 WSL 2 实验报告

正式批次 formal.8CCBEs 完成了 16 个独立会话。其中 12 个压缩会话各完成 C1、C2，4 个对照未压缩。试跑与正式样本分别留存。

实验使用 Ubuntu 26.04.1、WSL 2、Node.js 24.22.1、DeepSeek Harness 0.2.2-rc.1 和 deepseek-official/deepseek-flash。每个会话运行在独立的 Bubblewrap 命名空间，使用非 root 用户和零有效 capabilities。启动时逐个检查 Windows 盘、9p/DrvFs 挂载和 WSL 互操作入口。行为测试对合成目录开放写入。正式批次使用仅允许 DeepSeek 官方 HTTPS 目标的临时转接，保留 TLS 校验。Linux 下 8 项测试、类型检查和构建通过。

## 两项缺口

- **S2 的完整条件。** B1 保住了登记的原始目录禁止修改条款。两个 B1 变体在 C1、C2 后均找不到缓存清理例外和「不确定先报告」的原文。B0 的四次对应观测仍可找到完整原文。登记表只覆盖了禁止条款，不能以其核验通过代替完整条件保留。
- **S3 的工具事实。** 四个 S3 会话均通过真实工具读到了文件中部的两项事实。B0 在 C1、C2 共 8 个事实观测中逐字保留 8 个。B1 在 C1 的两个变体中用不同措辞转述了两项事实，C2 的两个可见摘要均遗漏了它们。这些工具事实从未进入用户授权登记。语义标签仍需独立人工签核。

## 结论

工程结论为 **FIX_AND_RETEST**。两轮事务、已登记禁止条款、来源链和实际提示投递通过验证。S2 的例外和不确定条件，以及 S3 的第二轮事实保留，需要修复后另起批次验证。正式运行与结构化审计已经完成，最终语义标签仍待独立人工签核。
